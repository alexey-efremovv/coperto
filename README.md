# Стоп-лист

Тестовое задание для Coperto. Один экран, на котором менеджер видит меню смены, фильтрует его по цеху и статусу, ставит позиции в стоп-лист и возвращает их в продажу.

## Запуск

```bash
npm install
npm run dev
```

Ещё есть `npm run lint`, `npm run format:check` и `npm test` — там один тест на оптимистичное обновление и откат.

## Как устроено

Всё, что относится к фиче, лежит в `features/stop-list`: в `model` работа с данными (запросы, мутации, ключи кэша, фильтры, zod-схема), в `ui` компоненты. Кнопка, селект, бейдж и тосты вынесены в `shared/ui`, мок-бэкенд — в `server` и `app/api`.

На сервере рендерятся `page.tsx` и фильтры. Страница читает `searchParams`, валидирует их и передаёт фильтры дальше, а сами фильтры — обычные ссылки. Поэтому их состояние живёт только в URL и без лишнего кода переживает перезагрузку и кнопку «назад».

Клиентская часть начинается со `StopList`: список из TanStack Query, панель с формой, тосты. Список специально не загружается на сервере — он меняется оптимистично, и держать второй источник данных не хотелось.

## Решения

Постановка в стоп, редактирование и возврат в продажу сделаны одной мутацией. Она сразу меняет позицию в кэше, а при ошибке откатывает только её, чтобы не задеть строки, которые сохраняются в это же время. Одна zod-схема проверяет и форму, и тело запроса в route handler'е. В Zustand лежат только id позиции, для которой открыта панель, и тосты.

## Допущения

- Панель закрывается только после ответа сервера. Если сохранение упало, форма остаётся открытой с введёнными данными.
- Для позиции, которая уже в стопе, форма открывается в режиме редактирования и отправляет тот же `POST /stop` — отдельного эндпоинта в ТЗ нет.
- Время вводится через `datetime-local`, чтобы все правила срока можно было проверить руками.
- Список сам по себе не падает. Экран ошибки можно увидеть, если заблокировать запрос в DevTools.
